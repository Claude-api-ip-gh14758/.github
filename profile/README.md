<p>"专用"两个字落到具体工作上，含义差别很大。一个人维护三个号，和一支团队维护三十个号，需要的配置几乎相反：前者要简单省心、能随时停；后者要分组、要台账、要备线。所以先别问买几条，先看自己在哪个场景里。下面按四种常见规模拆开讲，每种都给出口配法、老号新号的处理方式，以及这个场景下最该盯住的那个指标。</p>

<h2>一、先定位：规模和分工决定配置</h2>
<p>定位的依据有两个：账号数量，以及有没有第二个人会碰这些账号。只有一个人用、号也不多的，把配置做到"自己看得懂"就够了；有交接、有分工的，配置必须做到"别人看得懂"。</p>
<h3>数量决定隔离方式</h3>
<p>十个号以内，一台机器配独立浏览器配置目录通常够用；超过二十个，就要按项目分组，每组一套出口和一个负责人，否则台账会先乱掉。分组的意义不是技术上的，而是让责任有落点。</p>
<h3>分工决定记录深度</h3>
<p>多人协作时，记录要包含"谁在什么时候用了哪个号、哪个出口"。单人使用时这条可以简化为"哪天换过线"。记录深度按最坏情况设计：假设明天有人离职，接手的人能不能看懂。</p>

<h2>二、场景一：独立开发者，一到三个号</h2>
<p>这个场景的痛点是"不想为偶尔用一次付整月的钱"。技术上反而不复杂，一条固定地址加一套浏览器配置就能跑起来。</p>
<h3>出口配法</h3>
<p>按量计费优先，用多少算多少；需要连续登录的那一个号单独给固定地址，其余两个用按会话分配的出口。这样核心号的环境稳定，边缘号不占月费。</p>
<h3>这个场景最该盯的指标</h3>
<p>是"能否随时停"。接口调试常常一周用一次，包月等于白付三周。选择时把暂停规则问清：能否中途停、停了地址保留多久、恢复要不要重新配置。这三点比单价重要。固定住宅地址的月费大致几十到一两百元一条，按量出口常见每 GB 几元到十几元，仅供参考。</p>

<h2>三、场景二：跨境团队，五到二十个号</h2>
<p>这个场景的痛点是交接。人一换，环境就要重建，重建期间账号处于不稳定状态。所以配置要围绕"可移交"来设计。</p>
<h3>出口与账号一对一，另留一条备用</h3>
<p>每个号固定一条出口，额外留一条备用线，只在主线路故障时切入。备用线平时不上号，避免把两个号的历史混在一条地址上。</p>
<h3>交接只移交环境，不移交密码</h3>
<p>把账号、出口地址、浏览器配置目录、时区语言设置做成一份移交单，接手的人按单核对，不重建环境。这样登录环境连续，验证请求会少很多。交接完成后观察三天，把这三天的一次通过率记进台账，作为这次交接的质量分。</p>

<h2>四、场景三：工作室批量，二十个号以上</h2>
<p>规模上去之后，单点问题会变成系统问题：一条地址被标记，牵连的是一组号；一次误操作，影响的是整批配置。这个场景要做的是分组和分散。</p>
<h3>按项目分组，组间地址不重叠</h3>
<p>每组一套出口池，组与组之间的地址段尽量不重叠，至少不要落在同一个 /24。这样某一组出问题时，其他组不受影响，排查范围也被限定在一组之内。</p>
<h3>老号与新号分池跑</h3>
<p>老号需要的是稳定，新号需要的是干净。两者混在一个池子里，老号的历史会跟着地址带给新号，新号的注册行为也可能影响老号的地址评价。可行做法是物理分开：老号池固定地址、低频操作；新号池用新的地址段，观察到稳定后再决定是否转池。转池时连同浏览器配置一起迁，不要只换出口。</p>

<h2>五、场景四：企业内系统对接</h2>
<p>这一类的诉求和前面三种都不同：不是人在用，是系统在调。重点从"环境像不像真人"转到"调用能不能追溯"。</p>
<h3>按服务或按接口配，不按人配</h3>
<p>系统调用没有"人"的概念，出口按服务划分更合理。每个服务一条或一组出口，日志里记录服务名与时间，出问题能定位到具体服务而不是整个团队。</p>
<h3>要留得住的日志</h3>
<p>至少记四样：调用时间、出口地址、目标接口、返回码。日志保留周期按内部合规要求定，通常不低于三个月。这类场景不要用按会话切换的出口，地址频繁变化会让日志失去可比性。</p>

<h2>常见问答</h2>
<h3>三个号也需要买"专用"吗？</h3>
<p>答：需要的是"地址不与他人共用"，规模小不代表可以共用。三个号共用一条地址，一次异常会同时影响三个，排查时也无法区分。小规模更该简单：一号一条，问题少一半。</p>
<h3>老号被要求验证，新号要不要一起停？</h3>
<p>答：不用，前提是两者地址确实分开。分开跑的池子，一边的问题不会传到另一边。要确认的是两者不在同一 /24，也不共用浏览器配置目录，这两点做不到，"分开"只是名义上的。</p>
<h3>团队交接要留哪些记录？</h3>
<p>答：账号编号、出口地址、ASN、浏览器配置目录名、时区与语言、上次变更时间、接手人。七项齐了，接手的人不用问任何问题就能上手。</p>
<h3>按项目分组之后，一个人管多个组会不会乱？</h3>
<p>答：会，所以要限制交叉。一个人尽量只负责一组，跨组操作要登记。分组的意义就是把人、号、出口三者对应起来，交叉越多，这个对应关系越容易断。</p>
